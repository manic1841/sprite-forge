Cut a Recording in the workbench that runs on the store.

Ingest the GIF, mark a Segment on the filmstrip, repair the placed frames, commit. The rail lists what the store holds; every write lands on disk.

The workbench mounts here. It reads the store through the local server, so open this page from pnpm web rather than as a file.

Start it with SPRITE_FORGE_STORE=./store pnpm web, then reload.

The mount is live. Open the tabs to step frames, re-cut a Segment, align a Sequence or write an Export; every write goes through the local server and lands in store/.

  • Reads store/recordings

    Every Recording in the rail is a folder on disk, its cut list stored beside the frames.

  • Writes store/characters/hero/drafts

    A repair replays as an operation script, so the Draft can be re-cut without touching the Recording.

  • Commits store/characters/hero/clips

    The Clip lands with its provenance sidecar and the rail offers it back on the next read.

Does the tool work with any emulator?

It ingests animated GIFs. The pipeline is built for mGBA's output, and any capture with a steady background keys the same way.

Where does the tool's workbench run?

On your machine, with Node 20 or later. The web workbench is a dev server and ships nothing.

Can I edit a Clip in the store?

No. A committed Asset is immutable; Fork starts a new Draft and keeps the lineage.

How does the store lose a Clip's background?

Extract samples a corner pixel and keys it out at a tolerance of 24. Repair clears what is left on the frames.
